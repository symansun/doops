# dev / 114 DoOps Agent Deployment

This document records the stable deployment boundary for the dev Kubernetes
environment. It intentionally excludes the host address, passwords, private
keys, kubeconfig contents, registry credentials, and Gateway tokens.

## Environment Identity

- Local SSH recovery alias: `dev` or `dev-114`
- DoOps target: `gw-114-k8s`
- Gateway identity: `doops-114-k8s/master-1`
- Kubernetes namespace: `kube-system`
- Agent workload: `deployment/doops-agent-gateway`
- Agent container: `doops-agent`
- Gateway URL: `https://doops.l8ai.cn`

The SSH alias is maintained only in the operator's local `~/.ssh/config`.
Normal operations use the DoOps target. SSH is reserved for initial bootstrap
and Agent recovery when the installed Agent cannot execute the current
structured Kubernetes protocol.

## Preflight

Verify local key-based recovery access without prompting for a password:

```bash
ssh -o BatchMode=yes dev \
  'hostname && kubectl -n kube-system get deployment doops-agent-gateway'
```

Verify the Gateway route:

```bash
doops -session dev-114-preflight targets --target gw-114-k8s
```

Before changing the image, record the current immutable image and confirm the
candidate image was produced by a successful `main` CNB build:

```bash
ssh dev \
  'kubectl -n kube-system get deployment doops-agent-gateway \
    -o custom-columns="IMAGE:.spec.template.spec.containers[0].image"'
```

Do not deploy a floating tag. Use
`docker.cnb.cool/l8ai/ai/doops.sh@sha256:<verified-ci-digest>`.

## Image-Only Upgrade

Use this recovery path only when the runtime contract is unchanged and the
current Agent cannot perform `doops_k8s`. The command, environment variables,
probes, volumes, node selector, tolerations, and replica count must remain
unchanged.

```bash
ssh dev \
  'kubectl -n kube-system set image \
    deployment/doops-agent-gateway \
    doops-agent=docker.cnb.cool/l8ai/ai/doops.sh@sha256:<verified-ci-digest> &&
   kubectl -n kube-system rollout status \
    deployment/doops-agent-gateway --timeout=300s'
```

If the runtime contract changes, do not use `set image`. Reconcile the complete
workload from the reviewed Helm release values through an external release
controller.

## Verification

Read back the actual image and stable Pod state:

```bash
ssh dev \
  'kubectl -n kube-system get deployment doops-agent-gateway \
    -o custom-columns="READY:.status.readyReplicas,IMAGE:.spec.template.spec.containers[0].image";
   kubectl -n kube-system get pods -l app=doops-agent-gateway \
    -o custom-columns="NAME:.metadata.name,READY:.status.containerStatuses[0].ready,IMAGEID:.status.containerStatuses[0].imageID,RESTARTS:.status.containerStatuses[0].restartCount"'
```

Then verify the public control path:

```bash
doops -session dev-114-verify targets --target gw-114-k8s
doops -session dev-114-verify exec --target gw-114-k8s \
  --cmd 'do-agent --version && kubectl get nodes'
doops -session dev-114-verify k8s get pods --target gw-114-k8s \
  --namespace kube-system --output wide
```

The deployment is complete only when the workload is ready, the Pod `imageID`
matches the requested digest, the target reconnects to Gateway, and both
`exec` and structured `k8s` reads succeed.

## Rollback

Rollback uses the previous immutable digest recorded during preflight:

```bash
ssh dev \
  'kubectl -n kube-system set image \
    deployment/doops-agent-gateway \
    doops-agent=docker.cnb.cool/l8ai/ai/doops.sh@sha256:<previous-digest> &&
   kubectl -n kube-system rollout status \
    deployment/doops-agent-gateway --timeout=300s'
```

After rollback, repeat all verification steps. Never roll back to a floating
tag or restore credentials from repository files.
